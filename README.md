# Панель управления университетом (Shakarim)

Одностраничное приложение на «ванильном» JavaScript без сборщика. Работает как статический сайт (GitHub Pages) и опционально синхронизируется с Google-таблицей через Apps Script. Раньше это был один HTML-файл; теперь код разнесён по модулям, чтобы правки касались небольших файлов.

## Как это устроено

`index.html` — только разметка (шапка, вкладки, секции, модальное окно). Он подключает `styles.css` и по очереди все файлы из `js/`. Файлы — обычные `<script>` (не модули), поэтому порядок подключения важен: он совпадает с порядком, в котором функции определялись в исходном едином файле. Меняется поведение только того файла, который вы правите, — остальные не трогаются.

Данные лежат в `localStorage` браузера и (если настроена синхронизация) в Google-таблице. Публикация сайта данных не затрагивает.

```

  helpers.js          esc/fmt/money, unitPath, empBase/supTotal, период — общие утилиты
  accruals.js         начисления (справочник ставок, расчёт)
  tabs.js             переключение вкладок + гейтинг по ролям
  structure.js        дерево подразделений (renderTree)
  orgchart.js         визуальная оргсхема (зум/панорама)
  employees.js        таблица штата (renderEmployees)
  modals.js           ядро модалки + модалки подразделения и сотрудника (с доплатами)
  analytics.js        аналитика ФОТ
  data-io.js          экспорт/импорт JSON, CSV сотрудников
  render-all.js       renderAll() — оркестратор перерисовки (правьте при добавлении модуля)
  seed.js             демо-данные при первом запуске
  engine.js           РОЛИ, аудит, универсальный CRUD-движок (ENT), fieldInput, таблицы
  dashboard.js        сводная панель (KPI по всем модулям)
  calc.js             сценарный калькулятор ФОТ («что если»)

  budget.js           доходы/расходы по статьям
  contingent.js       группы контингента
  inventory.js        инвентарь, амортизация, МОЛ, движение имущества
  plan.js             план развития: заявки (workflow) + мониторинг план/факт
  settings.js         роли, справочники, хаб импорта, журнал аудита
  import.js           универсальный импорт по шаблону (CSV) для всех разделов
  programs.js         образовательные программы + загрузка по корпусам

backend/

docs/
  roadmap.md          стратегический roadmap развития
```

## Правила при редактировании

- **`init.js` всегда подключается последним** — он запускает приложение, когда все функции уже определены.
- Добавляете новый модуль-вкладку? Обычно нужно тронуть только: `index.html` (кнопка вкладки + пустая секция), новый `js/<модуль>.js`, одну строку в `render-all.js` и, при необходимости, `state.js` (новая коллекция) и `engine.js` (описание сущности в `ENT`).
- Порядок тегов `<script>` в `index.html` менять не нужно; при добавлении файла ставьте его до `init.js`.
- Это не ES-модули: функции и переменные верхнего уровня общие для всех файлов. Не заводите одинаковые имена в разных файлах.

## Запуск

Локально: откройте `index.html` в браузере (двойным кликом). Всё работает офлайн; синхронизация — по желанию.

Публикация: залейте содержимое папки в репозиторий → Settings → Pages → Deploy from a branch → main /(root).

Бэкенд (необязательно): см. комментарии в `backend/Code.gs` — создать таблицу, вставить код, задать `API_KEY`, развернуть как веб-приложение, URL и ключ ввести в приложении по кнопке «Синхронизация».
